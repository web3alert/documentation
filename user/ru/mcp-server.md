# MCP Server

Web3alert предоставляет три пути по протоколу Streamable HTTP.

| Путь | Набор инструментов | Аутентификация |
| --- | --- | --- |
| `/mcp/agent` | [14 инструментов](#endpoint-для-агентов) для аккаунта, платежей, подписок и доставки | Публичный список. Для вызовов нужен ключ Bearer. |
| `/mcp/agent/build` | 19 инструментов, включая 14 инструментов для агентов и [5 инструментов сборки](#build-endpoint) | Публичный список. Для вызовов нужен ключ Bearer. Инструменты сборки требуют Advanced или Pro. |
| `/mcp` | [Полный набор инструментов создания и редактирования](#remote-mcp-endpoint) | Ключ Bearer в каждом запросе. |

В записи `io.web3alert/agent` реестра MCP заголовок `Authorization` отмечен как необязательный. Описание сервера доступно в [публичном репозитории MCP](https://github.com/web3alert/mcp).

## Аутентификация

Оба пути для агентов принимают одиночные сообщения `initialize`, `ping`, `tools/list` и уведомления без токена. Вызовы инструментов и пакетные запросы требуют заголовка `Authorization: Bearer <agent-key>`. В пакете может быть до 20 сообщений. Полный интерфейс создания и редактирования требует заголовка даже для получения списка инструментов. Все три пути проверяют переданный ключ и возвращают HTTP `401`, если он недействителен.

Создайте ключ на [странице Agents](https://web3alert.io/agents) или [зарегистрируйтесь с кошельком](agents.md). Ключ действует от имени аккаунта в рабочем пространстве, к которому привязан. Доступные операции зависят от прав ключа, применимого тарифа и прав аккаунта в пространстве.

После отзыва API сразу отклоняет токен. Пока MCP хранит результат проверки в кеше, вызов инструмента для агентов, дошедший до API, возвращает `access_denied`. Благодаря кешу запросы `initialize` и `tools/list` с отозванным токеном могут еще успешно выполняться до 30 секунд. Когда MCP повторно проверяет отозванный токен, сервер возвращает HTTP `401`.

| Статус HTTP | Что делать |
| --- | --- |
| `401` | Обязательный Bearer-токен отсутствует либо переданный токен недействителен, неизвестен серверу или отозван. Отправьте заголовок с действующим токеном. Получите новый токен, если у вас его нет или сервер его больше не распознает. |
| `403` | Сервер отклонил origin клиента (`forbidden_origin`) или account не прошел проверку доступа к MCP (`mcp_access_denied`). В зависимости от ошибки проверьте заголовок `Origin` клиента или данные account. |
| `429` | Входной прокси ограничил запросы с вашего IP или API ограничил частоту проверки учётных данных. Соблюдайте `Retry-After` перед повтором. |
| `503` | Проверка токена временно недоступна. Подождите указанное в `Retry-After` время и повторите запрос с тем же токеном. |

По умолчанию каждый процесс сервера разрешает 120 вызовов инструментов в минуту на аккаунт. Лимит общий для трёх эндпоинтов и всех ключей и токенов аккаунта. При исчерпании лимита инструмент возвращает `rate_limited` и время ожидания в секундах в поле `retryAfter`.

Ошибки инструментов возвращаются отдельно от ошибок аутентификации HTTP.

| Ошибка | Причина |
| --- | --- |
| `insufficient_scope` | У ключа нет нужного права. См. [сообщение об отсутствии права `code`](api.md#auth). |
| `key_not_allowed` | Операция требует сессии аккаунта. Это также относится к покупке ключом, пока действует тариф с автопродлением. |
| `spend_cap_exceeded` | Покупка превысит месячный лимит ключа в EUR. |
| `not_in_plan` | Тариф рабочего пространства не включает входящие события или историю доставки. |
| `plan_required` | Сборка доступна аккаунтам на Advanced или Pro. |
| `insufficient_balance` | Баланса в EUR не хватает для покупки тарифа. |
| `api_error` | При вызове `buy_plan` незавершённое оформление или действующий более высокий тариф могут заблокировать покупку до списания средств. Инструмент передаёт сообщение API. Сначала решите вопрос с текущим тарифом или оформлением. |
| `x402_unavailable` | Пополнения в USDC недоступны. |
| `rate_unavailable` | Справочный курс ЕЦБ недоступен. |
| `no_current_workspace` | Инструменту нужно текущее пространство, но API его не вернул. |
| `not_tested` | Перед активацией последний тест черновика должен вернуть `matched`. |
| `draft_expired` | Срок действия черновика истёк. |
| `retryable` | Не удался запрос к поставщику данных сети или исчерпан лимит тестов пространства. |
| `private_project_limit` | Создание приватного проекта агента превысит лимит проектов аккаунта. |
| `trigger_limit` | Активация триггера превысит лимит тарифа. |
| `not_found` | Цель недоступна. При сборке это может быть неизвестная сеть, отсутствие проверенного ABI, отсутствие IDL или неизвестный паллет, если среда выполнения указала причину. Общая ошибка при поиске IDL или паллета даёт `retryable`. Недоступное событие, черновик или триггер также могут дать `not_found`. Перегруженный обозреватель также может вернуть `not_found` для ABI. Если контракт в обозревателе верифицирован, повторите запрос через минуту. |
| `request_id_conflict` | Этот `requestId` активации уже использован для другого черновика в пространстве. |

## Обновление существующих клиентов

Передавайте ключ в заголовке `Authorization: Bearer <agent-key>`. Эндпоинт `/mcp` требует этот заголовок в каждом запросе и работает без сессий MCP. Уберите ключ из URL и тела запроса.

Существующие токены сессий работают, пока сервер их не отзовёт. Для новых подключений используйте ключ агента.

В Claude Code выполните эти команды в проекте, где вы используете Web3alert.

1. Выполните `claude mcp list`, чтобы проверить, есть ли запись с именем, которое вы хотите заменить. Чтобы узнать область настройки показанной записи, выполните `claude mcp get web3alert` или `claude mcp get web3alert-agent`.
2. Удалите запись, указав её область, например командой `claude mcp remove --scope user web3alert` или `claude mcp remove --scope local web3alert`. После удаления может появиться одноимённая запись из другой области. Повторяйте шаги 1 и 2, пока имя не исчезнет из списка.
3. Добавьте новую запись командой `claude mcp add` из примера для нужного эндпоинта.

В Claude Desktop, Cursor и VS Code измените URL и заголовки в существующей записи. См. [примеры настройки удалённого эндпоинта](#remote-mcp-endpoint).

## Endpoint для агентов

Инструменты работают в пространстве, к которому привязан ключ. Для работы в другом пространстве создайте ключ в нём.

| Инструмент | Что делает |
| --- | --- |
| `get_account` | Возвращает ID, имя, тариф, баланс в EUR, лимиты тарифа и доступные счётчики подписок, а также права, срок действия, месячный лимит и расходы ключа. |
| `get_topup_requirements` | Запрашивает котировку пополнения от 5 до 500 € в USDC. Подпишите платёж самостоятельно своим кошельком. Нужно право `manage`. Перед подписью проверьте [URL платежа, сеть и актив](api-billing.md#post-api-billing-wallet-x402-topup). |
| `buy_plan` | Покупает Advanced или Pro с баланса в EUR без автопродления. Требуются `spend` и новый `requestId` длиной 8–64 символа, например сгенерированный UUID. Используйте тот же ID только при повторе этой покупки. |
| `find_triggers` | Ищет триггеры сетей EVM и Substrate в публичном каталоге. Также ищет триггеры в текущем воркспейсе. |
| `get_trigger` | Показывает inputs для выполнения trigger, поля доставляемых событий и поля, которые можно использовать в `conditions`. |
| `list_webhooks` | Возвращает `fullname`, имя и URL каждого webhook, зарегистрированного в workspace. Поле `signed` показывает, есть ли у вебхука секрет подписи. |
| `add_webhook` | Регистрирует вебхук с HTTPS-адресом без учётных данных. Если при проверке имени в воркспейсе уже есть ресурс с таким именем, инструмент отклоняет запрос с ошибкой `webhook_exists`. Секрет подписи доступен только в ответе `add_webhook` в поле `signingSecret`. Если заменить его позже, секрет изменится для всех получателей этого эндпоинта. |
| `remove_webhook` | Удаляет вебхук по полному имени в текущем пространстве. Нужно право `manage`. Возвращает `webhook_in_use`, если вебхук используется активной подпиской в том же пространстве. |
| `create_subscription` | Создаёт подписку с одним способом доставки: `webhook` или `inbox: true`. Передайте обязательные входные параметры и необязательные `conditions`. При `inbox: true` код `resource_name_in_use` означает, что имя inbox уже занято другим ресурсом. Попросите участника пространства с ролью `owner` или `admin` устранить конфликт. Указывайте уникальный `title` для каждой новой подписки через `create_subscription`. Если ответа нет, вызовите `list_subscriptions` и поищите подписку по названию. Если совпадений нет, подождите и проверьте снова, поскольку исходный запрос всё ещё может создать подписку. Если по названию результат неясен, проверьте правила и действия из [GET /api/subscriptions](api-subscriptions.md#get-api-subscriptions). Если результат остаётся неизвестным, остановитесь и выясните, что произошло, прежде чем повторять создание. |
| `list_subscriptions` | Возвращает ID, названия, состояния, triggers, webhooks и время создания subscriptions. |
| `set_subscription_state` | Приостанавливает (`off`) или возобновляет (`on`) subscription. |
| `remove_subscription` | Удаляет подписку. Повторные попытки доставки вебхуков прекращаются примерно в течение 10 секунд. Попытка, время которой наступит в этот интервал, ещё может быть отправлена. |
| `read_events` | Читает входящие события платного пространства, начиная со старых. Передавайте `nextCursor` как `after` в том же пространстве. `gap: true` указывает на пропуски среди сохранённых событий до первого результата или внутри страницы. Пустая страница может показать пропуск, если более новые события больше не хранятся. Недоставленные события смотрите через `get_delivery_log`, когда доступна история. Нужно право `read`. Если тело входящего события больше 64 KiB, событие приходит с `body.truncated: true` и без `body.object`. Проверьте этот флаг перед обработкой. |
| `get_delivery_log` | Показывает результаты доставки в воркспейсе или для отдельной подписки. Для истории оповещений используется тариф первого аккаунта с ролью владельца в списке доступа воркспейса. Если такого аккаунта нет, API проверяет тариф аккаунта, который сделал запрос. Если в тариф не входит история, инструмент возвращает `not_in_plan`. Записи каналов вебхуков содержат `eventId` и `attempt`. `nextAttemptAt` содержит время в формате ISO, на которое была запланирована следующая попытка в момент создания записи, или `null`, если в записи нет запланированной повторной попытки. |

Значение `nextAttemptAt` остаётся прежним даже после выполнения или отмены повторной попытки. Чтобы узнать результат доставки, найдите более позднюю запись с тем же `eventId`. Если повторные попытки прекратились из-за приостановки или удаления подписки либо истёк срок хранения попытки в очереди, Web3alert не создаёт итоговую запись, а по её отсутствию нельзя определить ни исход доставки, ни то, ожидается ли ещё повторная попытка.

`limits.maxSubscriptions` ограничивает количество созданных вами активных подписок на проекты без статуса Free суммарно во всех воркспейсах. На тарифе Free лимит равен 5. Подписки на проекты Free не входят в лимит.

При достижении лимита subscriptions для tier вызов `create_subscription` может вернуть ошибку `subscription_limit_reached`. Успешное создание или возобновление (вызов `set_subscription_state` с `on`) может вернуть `state: "blocked"` и `blockedReason: "subscription_limit_reached"`. Прежде чем считать доставку активной, убедитесь, что вернулся `state` со значением `on`.

Используйте [эндпоинт сборки](#build-endpoint), чтобы создать приватный триггер для события в блокчейне.

### Claude Code

```bash
printf 'Ключ агента Web3alert: ' && read -rs WEB3ALERT_KEY && echo && [ -n "$WEB3ALERT_KEY" ] && claude mcp add --scope user --transport http web3alert-agent https://web3alert.io/mcp/agent --header "Authorization: Bearer $WEB3ALERT_KEY"
```

### Claude Desktop и Cursor

В Claude Desktop добавьте запись в `mcpServers` в файле `claude_desktop_config.json`. В Cursor используйте личный файл `~/.cursor/mcp.json`.

```json
{
  "mcpServers": {
    "web3alert-agent": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://web3alert.io/mcp/agent",
        "--header",
        "Authorization:${AUTH_HEADER}"
      ],
      "env": {
        "AUTH_HEADER": "Bearer YOUR_AGENT_KEY"
      }
    }
  }
}
```

### VS Code

Для подключения через редактор добавьте запись в `servers` в файле `.vscode/mcp.json` и передайте переменную `WEB3ALERT_KEY` в окружение процесса VS Code.

```json
{
  "servers": {
    "web3alert-agent": {
      "type": "http",
      "url": "https://web3alert.io/mcp/agent",
      "headers": {
        "Authorization": "Bearer ${env:WEB3ALERT_KEY}"
      }
    }
  }
}
```

## Эндпоинт сборки {#build-endpoint}

Используйте `https://web3alert.io/mcp/agent/build` с теми же настройками и заголовком Bearer. Список включает 14 инструментов выше и эти 5. Аккаунты Free видят их в списке и получают `plan_required` при вызове. Инструменты сборки работают без права `code`.

`find_contract` и `plan_trigger` используют встроенные источники сетей Web3alert. Передайте короткое имя, например `ethereum`, `base`, `arbitrum-one`, `polkadot` или `solana`, либо имя в формате `common.<chain>` или `common.source.<chain>`. Если сеть неизвестна и для указанного типа цели доступны короткие имена, сообщение об ошибке `not_found` перечисляет их после `Supported:`.

| Инструмент | Право | Действие |
| --- | --- | --- |
| `find_contract` | `read` | Находит точные сигнатуры событий по ABI контракта, IDL Solana или метаданным Substrate. Для EVM возвращает функции и `recentCount` по каждому событию за последние `recentBlocks` блоков, максимум 1 000. Диапазон может быть меньше, если провайдер отклонил широкий запрос. `recentBlocks` равно `null`, если прочитать блоки не удалось, а также для Solana или Substrate. Значение `0` означает, что в указанном диапазоне не было подходящих логов. |
| `plan_trigger` | `manage` | Генерирует черновик для события без написания кода. Возвращает `draftId`, предварительное полное имя, входные и фильтруемые поля, схему результата и срок действия. |
| `test_trigger` | `read` | Тестирует черновик на недавнем примере или воспроизводит указанный блок либо слот. Поиск в EVM охватывает не более 1 000 последних блоков. Поиск проверяет до 12 недавних слотов для Solana и до 12 недавних блоков для Substrate. Если в EVM уже прочитан хотя бы один диапазон логов без совпадений, ответ провайдера с ошибкой, включая тайм-аут на его стороне, или отказ среды выполнения без конкретной причины для более старого диапазона может завершить поиск с `no_match`. Этот результат охватывает только прочитанные диапазоны. Ошибки транспорта, истечение срока поиска и невозможность прочитать хотя бы один диапазон дают `retryable`. Если известно, где произошло событие, или нужно пропустить поиск, передайте его `slot` для Solana или `block` для EVM или Substrate в `test_trigger`. Для более раннего события EVM укажите его `block` явно. Если из-за лимита тестов пространства API возвращает HTTP `429` с `error.code: "retryable"`, MCP сообщает об ошибке инструмента. Увеличьте паузу перед повтором. Успешный ответ инструмента может содержать `result: "retryable"`. |
| `activate_trigger` | `manage` | Сохраняет черновик, прошедший последний тест. При первой успешной активации создаётся приватный проект агента и учитывается в лимите аккаунта. При повторе для того же черновика передавайте тот же `requestId`. Использование его для другого черновика даёт `request_id_conflict`. Возвращённое полное имя можно использовать для подписок. Если проект агента в пространстве создал другой участник, при активации учитывается тариф создателя проекта для проверки единиц триггеров. Если этот тариф больше не разрешает управление триггерами, возвращается `plan_required`. Для активации нужен `requestId` длиной до 128 символов хотя бы с одним непробельным символом. Участник пространства с ролью `developer` может собрать и активировать триггер. Использовать полученное полное имя в `create_subscription` может только `owner` или `admin`. |
| `remove_my_trigger` | `manage` | Удаляет триггер из этого проекта. Возвращает `trigger_in_use`, если триггер используется активной подпиской в том же пространстве. |

При прямом удалении триггера или вебхука проверяются активные (`on`) подписки в рабочем пространстве этого триггера или вебхука. Приостановите или удалите их перед повторной попыткой. Удаление проекта, рабочего пространства или аккаунта блокирует затронутые подписки. Активная подписка на публичный триггер в другом пространстве не препятствует прямому удалению.

## Remote MCP endpoint

Используйте `https://web3alert.io/mcp` для доступа ко всем инструментам работы с проектами, триггерами, шаблонами, подписками, ресурсами, источниками данных и диагностикой. Отправьте аутентифицированный запрос `tools/list`, чтобы получить полный список.

Чтобы добавить эндпоинт в Claude Code, выполните команду в Bash или Zsh и введите ключ агента в скрытом приглашении.

```bash
printf 'Ключ агента Web3alert: ' && read -rs WEB3ALERT_KEY && echo && [ -n "$WEB3ALERT_KEY" ] && claude mcp add --scope user --transport http web3alert https://web3alert.io/mcp --header "Authorization: Bearer $WEB3ALERT_KEY"
```

Используйте тот же файл конфигурации Claude Desktop или Cursor. Для [VS Code](#vs-code) используйте тот же пример `servers` с адресом `https://web3alert.io/mcp`.

```json
{
  "mcpServers": {
    "web3alert": {
      "command": "npx",
      "args": [
```

### Права ключей агентов {#authoring-permissions}

Для следующих инструментов `/mcp` ключу агента требуется `code` в дополнение к [обычным правам](api-triggers.md#agent-key-permissions).

- `manage` + `code` — `web3alert_upsert_trigger`, `web3alert_patch_trigger`, `web3alert_patch_triggers`
- `manage` + `code` — `web3alert_test_trigger`, `web3alert_test_trigger_block`, `web3alert_test_trigger_provider`
- `read` + `code` — `web3alert_preview_trigger`

При сохранении с `save=true` следующим инструментам импорта также нужны `manage` и `code`. Если опустить `save`, то `saveDrafts=true` действует так же.

- Solana — `web3alert_import_solana_program`, `web3alert_import_solana_trigger`, `web3alert_import_solana_entries`
- Substrate — `web3alert_import_substrate_trigger`, `web3alert_import_substrate_entries`, `web3alert_import_substrate_pallets`
