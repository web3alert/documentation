# Account API

Endpoints Account работают с текущим пользователем, его метаданными, аватаром и выбранным workspace.

Для аутентифицированных запросов передавайте Bearer-учётные данные. Для управления ключами и изменения сессий нужен токен сессии аккаунта. Публичные операции входа и получения доступа указаны ниже.

## POST /api/token

`POST /api/token` не требует существующего header `Authorization: Bearer <token>`. Учетные данные provider в `credentials` подтверждают identity через выбранный `app`.

Каждый успешный запрос создает новый постоянный Bearer-токен; ранее выданный токен не переиспользуется и не возвращается. При первом успешном входе для identity сервис также может создать account и workspace.

<!-- api-contract: auth=provider-credentials; existing-bearer=not-required; token=fresh-persistent; first-login=may-provision-account-workspace -->

Аргументы: path/query аргументов нет.

Тело запроса:

| Поле | Обязательное | Описание |
| --- | --- | --- |
| `app` | Да | Имя auth app/provider. |
| `credentials` | Да | Учетные данные выбранного provider. |
| `claim` | Нет | Токен из ссылки на получение доступа к аккаунту кошелька, для входа через Telegram или Google. |

Ответ: [TokenResponse](types.md#tokenresponse).

Пример запроса (header `Authorization` намеренно отсутствует):

```http
POST /api/token
Content-Type: application/json

{
  "app": "google",
  "credentials": {
    "credential": "<provider-issued-credential>"
  }
}
```

Пример ответа:

```json
{
  "token": "<new-bearer-token>"
}
```

Учетные данные provider и возвращенный токен — секреты. Отправляйте их только по HTTPS; не записывайте в логи, не публикуйте и не добавляйте в commits.

При успешном входе с `claim` логин привязывается к аккаунту кошелька, ссылка погашается, а сервер выдаёт токен сессии этого аккаунта. Если логин уже принадлежит другому аккаунту, сервер возвращает `409 login_already_linked`, а ссылка остаётся действительной. Недействительная ссылка даёт `404 claim_not_found` без создания аккаунта.

## DELETE /api/token

Отзывает токен, которым аутентифицирован этот запрос.

Требуется токен сессии аккаунта. При выходе из приложения эта операция вызывается для текущей сессии браузера.

Отправьте запрос без path/query аргументов и без тела. Дополнительные параметры не позволяют выбрать другой токен или account.

```http
DELETE /api/token
Authorization: Bearer YOUR_SESSION_TOKEN
```

При успехе сервер возвращает `204 No Content` с пустым телом. Этот endpoint доступен, даже если account исчерпал свой лимит запросов к API.

## DELETE /api/tokens

Отзывает все токены аутентифицированного account, включая токен, использованный в этом запросе.

Требуется токен сессии аккаунта. Ключи агентов отзываются отдельно через `DELETE /api/keys/:id`.

Отправьте запрос без path/query аргументов и без тела. Дополнительные параметры не позволяют выбрать другой токен или account.

```http
DELETE /api/tokens
Authorization: Bearer YOUR_SESSION_TOKEN
```

При успехе сервер возвращает `204 No Content` с пустым телом. Этот endpoint доступен, даже если account исчерпал свой лимит запросов к API.

## GET /api/me

Возвращает текущий account, identity, tier, memberships и выбранный workspace.

Для запроса с ключом нужно право `read`. В ответ добавляется `key` с полями `id`, `name`, `scopes`, `monthlyCapEur`, `spentThisMonthEur` и `expiresAt`.

Аргументы: нет.

Тело запроса: нет.

Ответ: [Me](types.md#me).

### Лимиты тарифа {#me-limits}

Ответ также содержит `limits` для тарифа аккаунта, от имени которого сделан запрос.

| Поле | Тип | Описание |
| --- | --- | --- |
| `limits.maxSubscriptions` | `number \| null` | Общий для аккаунта лимит на созданные им активные подписки на проекты без статуса Free во всех воркспейсах. Подписки на проекты Free не входят в лимит. `null` означает отсутствие ограничения. |
| `limits.canRunTests` | `boolean` | Разрешён ли запуск тестов на этом тарифе. |
| `limits.alertHistory` | `object \| null` | Лимиты истории оповещений. `null` означает, что тариф не включает историю. |
| `limits.alertHistory.retentionDays` | `number` | Срок хранения истории оповещений в днях. |
| `limits.alertHistory.maxRecords` | `number \| null` | Максимальное число хранимых записей. `null` означает отсутствие ограничения. |

## POST /api/keys

Требуется токен сессии аккаунта. Создаёт ключ для текущего пространства. Передайте `{ name, scopes, monthlyCapEur?, expiresInDays? }`. Имя содержит 1–64 символа. Укажите `read` и при необходимости `manage` и `spend`. Лимит можно задать от 0 до 10 000 € с точностью до двух знаков, срок действия — 30, 90 или 365 дней. Чтобы оставить параметр без ограничения, опустите его или укажите `null`.

Возвращает `201` с `{ key, secret }`. Скопируйте `secret`, он показан только в этом ответе.

## GET /api/keys

Требуется токен сессии аккаунта. Возвращает `{ keys }` во всех пространствах аккаунта, от новых к старым, включая отозванные. Для каждого ключа возвращаются пространство, права, лимит, расходы за месяц, срок действия, статус и `connectedBy`.

## PATCH /api/keys/:id

Требуется токен сессии аккаунта. Передайте `{ name?, monthlyCapEur? }`, чтобы изменить ключ аккаунта. Укажите `null`, чтобы снять лимит. Возвращает `{ key }` или `404`, если ключ недоступен аккаунту.

## DELETE /api/keys/:id

Требуется токен сессии аккаунта. Отзывает ключ аккаунта. Возвращает `204 No Content`, в том числе при повторном отзыве, или `404`, если ключ недоступен аккаунту.

## POST /api/agent/siwe/nonce

Публичный. Тело запроса не требуется. Возвращает `{ nonce, issuedAt, expiresAt }`. Nonce действует 10 минут и используется один раз.

## POST /api/agent/siwe/verify

Публичный. Передайте `{ message, signature }`, подписанный внешним аккаунтом Ethereum (EOA). Используйте сообщение EIP-4361 версии `1`, полученный nonce, домен `web3alert.io`, URI того же источника и `issuedAt`, отличающийся от времени сервера не более чем на пять минут. Принимается любой ID сети.

Возвращает `{ account: { id, created }, key, secret, claimUrl }`. При первом входе создаются аккаунт Free и рабочее пространство. Каждый успешный вход выдаёт новый ключ со всеми правами, без лимита и срока действия. После привязки Telegram или Google `claimUrl` равно `null`. Используйте `secret` как Bearer-ключ.

Неудачная проверка возвращает `401 invalid_siwe`. Можно создать до 10 аккаунтов на IP за скользящий час и до 200 всего за скользящие сутки. При превышении лимита возвращается `429 signup_limited` с `Retry-After`. См. [пример SIWE](agents.md).

## POST /api/agent/claim-link

Требуется ключ агента с `manage`. Тело запроса не требуется. Возвращает `{ claimUrl, expiresAt }`. Новая ссылка заменяет предыдущую и действует семь дней. Для токена сессии возвращается `403 agent_key_required`. Если Telegram или Google уже привязан, возвращается `409 already_claimed`.

## GET /api/agent/claims/:token

Публичный для владельца ссылки. Возвращает `{ wallet, account: { name }, createdAt, expiresAt }`. Неизвестная, истёкшая, заменённая или использованная ссылка даёт `404 claim_not_found`. Для получения доступа передайте необязательное поле `claim` в `POST /api/token`.

Обновляет пользовательские метаданные.

Аргументы: нет.

Тело запроса:

| Поле | Обязательное | Описание |
| --- | --- | --- |
| `nickname` | Да | Отображаемое имя пользователя, 2-80 символов. Перед сохранением и возвратом удаляются начальные и конечные пробельные символы. |

Ответ: HTTP 200 OK.

| Поле | Обязательное | Описание |
| --- | --- | --- |
| `nickname` | Да | Сохраненный nickname без начальных и конечных пробельных символов. |
