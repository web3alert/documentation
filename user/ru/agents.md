# Для агентов

В каталоге Web3alert есть декодированные ончейн-события EVM, Substrate, Solana и HyperCore. Агент может использовать [10 инструментов MCP](mcp-server.md#endpoint-для-агентов), чтобы найти триггер, подписаться на него и получать подходящие события в формате JSON на свой вебхук.

## Скоро

- Вход через кошелёк, чтобы агенты могли создавать собственные аккаунты.
- Пополнение баланса в USDC через x402.
- Входящие для просмотра пропущенных событий.

## 1. Получите токен

Пользователь входит в [Web3alert](https://web3alert.io) и копирует персональный токен доступа из [настроек аккаунта](account.md#personal-access-token). Агенты пока не могут создавать собственные аккаунты. Выберите в приложении воркспейс, которым вы владеете или управляете. Для добавления вебхука, создания подписки и просмотра истории доставки нужна роль `owner` или `admin`.

## 2. Подключите MCP-клиент

Используйте Streamable HTTP по адресу `https://web3alert.io/mcp/agent` и передавайте заголовок `Authorization: Bearer <token>` в каждом запросе.

### Claude Code

Задайте токен в переменной `WEB3ALERT_TOKEN` в терминале и выполните эту команду.

```bash
claude mcp add --transport http web3alert-agent https://web3alert.io/mcp/agent \
  --header "Authorization: Bearer $WEB3ALERT_TOKEN"
```

### Claude Desktop и Cursor

Добавьте запись в `mcpServers` в файле `claude_desktop_config.json` для Claude Desktop (Settings → Developer → Edit Config) или в личном файле `~/.cursor/mcp.json` для Cursor. В примере используется мост `mcp-remote`, который запускается через `npx`. Замените пример токена своим значением.

```json
{
  "mcpServers": {
    "web3alert-agent": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://web3alert.io/mcp/agent",
        "--header",
        "Authorization:${AUTH_HEADER}"
      ],
      "env": {
        "AUTH_HEADER": "Bearer YOUR_PERSONAL_ACCESS_TOKEN"
      }
    }
  }
}
```

### VS Code

Для подключения через редактор добавьте запись в `servers` в файле `.vscode/mcp.json` и передайте переменную `WEB3ALERT_TOKEN` в окружение процесса VS Code.

```json
{
  "servers": {
    "web3alert-agent": {
      "type": "http",
      "url": "https://web3alert.io/mcp/agent",
      "headers": {
        "Authorization": "Bearer ${env:WEB3ALERT_TOKEN}"
      }
    }
  }
}
```

## 3. Создайте первую подписку

В этом примере заменяйте значения в угловых скобках результатами предыдущих вызовов. Вместо адреса из примера укажите HTTPS-адрес своего вебхука без имени пользователя и пароля. Выберите событийный триггер и передайте обязательные `inputs`, которые покажет `get_trigger`. В примере у триггера нет обязательных входных параметров.

1. `get_account({})` → Аккаунт, тариф, текущий воркспейс, баланс кошелька в EUR, лимиты тарифа и счётчики подписок, если они доступны.
2. `find_triggers({"kind":"event","limit":5})` → Подходящие триггеры из опубликованного каталога и текущего воркспейса, включая `fullname` каждого триггера.
3. `get_trigger({"trigger":"<trigger-fullname>"})` → Входные параметры триггера, поля события и поля для фильтрации.
4. `add_webhook({"name":"agent-events","url":"https://example.com/webhooks/web3alert"})` → `fullname`, имя и URL зарегистрированного вебхука. Сохраните полученный `signingSecret` для принимающей стороны. Инструмент возвращает его один раз.

   Если ответ `add_webhook` потерян, вызовите `list_webhooks`. Если эндпоинт существует, а его секрет вы не получили, используйте его `fullname` и тот же токен, чтобы заменить секрет через [`POST /api/resources/{fullname}/signing-secret`](api-resources.md#post-api-resources-fullname-signing-secret).

5. `create_subscription({"trigger":"<trigger-fullname>","webhook":"<webhook-fullname>","state":"on"})` → ID, название, итоговое состояние, триггер и вебхук подписки.
6. `get_delivery_log({"subscriptionId":"<subscription-id>"})` → Результаты доставки и `nextCursor`, если есть ещё результаты. Для истории оповещений используется тариф первого аккаунта с ролью владельца в списке доступа воркспейса. Если такого аккаунта нет, API проверяет тариф аккаунта, который сделал запрос. Если в тариф не входит история, инструмент возвращает `not_in_plan`.

   Если курсор не может продвинуться из-за того, что у 500 или более доставок одна и та же отметка времени, инструмент возвращает `api_error`. Уточните фильтр, например по статусу, и начните заново без курсора.

Убедитесь, что подписка вернулась со значением `state` равным `on`. После этого вебхук может получать подходящие события. Укажите новое имя вебхука или найдите уже зарегистрированный вебхук с помощью `list_webhooks`.

## Тело запроса вебхука

Ваш вебхук получает тело в формате JSON с ID события. Новые вебхуки получают подписанные доставки, и Web3alert автоматически повторяет попытки при сбоях, для которых предусмотрен повтор. Формат тела, проверка подписей, повторы и устранение дублей описаны в разделе [Вебхуки](webhooks.md).

## Лимиты

На тарифе Free аккаунт может иметь **до 5 созданных им активных подписок на проекты без статуса Free** суммарно во всех воркспейсах. Подписки на проекты Free не входят в лимит.

Эндпоинт для агентов создаёт подписки, которые доставляют оповещения только на вебхуки. На тарифе Free для каждой такой подписки по умолчанию действуют всплеск до 12 оповещений, постоянная скорость 1 оповещение в секунду и предел очереди в 15. Эти подписки не расходуют квоту доставки воркспейса.

Тариф Free позволяет делать 60 запросов в минуту к внешнему API. Тесты подписок и история оповещений доступны на тарифах Advanced и Pro. В обоих случаях API проверяет тариф первого владельца воркспейса и использует правило из шага 6, если владельца нет. Полные таблицы доступны в разделе [«Лимиты»](limits.md).

По умолчанию сервер MCP разрешает 120 вызовов инструментов на аккаунт в минуту. Оба эндпоинта используют общий лимит в каждом серверном процессе. `get_account` возвращает тариф аккаунта и те же [лимиты тарифа](api-account.md#me-limits), что и `GET /api/me`. Поле `limits` в ответе инструмента равно `null`, если API не передаёт лимиты тарифа. MCP может использовать сохранённый ответ `/me` до 30 секунд, поэтому смена тарифа может отразиться в `get_account` с такой задержкой.
