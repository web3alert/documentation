# Для агентов

В каталоге Web3alert есть декодированные ончейн-события из сетей EVM и Substrate, включая Ethereum, Polkadot и Kusama. Агент может использовать [14 инструментов MCP](mcp-server.md#endpoint-для-агентов), чтобы найти триггер, подписаться на него и получать подходящие события в формате JSON.

## 1. Получите ключ агента

### Создайте ключ в приложении

Войдите в [Web3alert](https://web3alert.io), выберите рабочее пространство, в котором вы владелец или администратор, и создайте ключ на [странице Agents](https://web3alert.io/agents). Ключ привязан к этому пространству. Скопируйте секрет при создании. Он показывается один раз.

У каждого ключа есть право `read`. Добавьте `manage`, чтобы регистрировать вебхуки, создавать подписки или запрашивать котировки для пополнения. Добавьте `spend`, чтобы покупать тарифы с баланса в EUR. Можно установить [месячный лимит расходов](limits.md#agent-payments) и срок действия 30, 90 или 365 дней. Оба ограничения необязательны.

Существующие токены сессий работают, пока владелец не выйдет из аккаунта или не отзовёт их. Для новых подключений используйте ключ агента.

### Зарегистрируйтесь с кошельком Ethereum

Агент с внешним аккаунтом Ethereum (EOA) может создать собственный аккаунт Free. Сначала запросите одноразовый nonce. Оба запроса SIWE публичные.

```http
POST /api/agent/siwe/nonce
Host: web3alert.io
```

```json
{
  "nonce": "exampleNonce123456",
  "issuedAt": "<ISO-8601 timestamp>",
  "expiresAt": "<ISO-8601 timestamp>"
}
```

Составьте сообщение EIP-4361 с полученными nonce и `issuedAt`, подставьте адрес и подпишите точный текст кошельком. Nonce действует 10 минут. Сервер проверяет, что `issuedAt` отличается от его времени не более чем на 5 минут.

```http
POST /api/agent/siwe/verify
Host: web3alert.io
Content-Type: application/json

{
  "message": "web3alert.io wants you to sign in with your Ethereum account:\n<your Ethereum address>\n\n\nURI: https://web3alert.io\nVersion: 1\nChain ID: 1\nNonce: <nonce>\nIssued At: <issuedAt>",
  "signature": "<wallet signature>"
}
```

Пример ответа `200`. Объект `key` показан в сокращённом виде.

```json
{
  "account": { "id": "<account-id>", "created": true },
  "key": { "id": "<key-id>", "scopes": ["read", "manage", "spend"] },
  "secret": "w3a_<key-secret>",
  "claimUrl": "https://web3alert.io/claim/<claim-token>"
}
```

При каждом входе создаётся новый ключ для первоначального рабочего пространства со всеми тремя правами, без лимита и срока действия. Используйте `secret` как Bearer-ключ. Повторный вход использует тот же аккаунт. После привязки Telegram или Google поле `claimUrl` равно `null`.

Передайте ссылку на получение доступа человеку, который будет управлять аккаунтом. На странице указаны кошелёк, дата создания аккаунта и срок действия ссылки, доступны кнопки входа через Telegram и Google. После входа открывается страница Agents, где можно просматривать и контролировать ключи и проверять тариф, баланс и расходы. Если логин уже привязан к другому аккаунту Web3alert, используйте другой. Последняя ссылка действует семь дней. Заменить её можно через [эндпоинт создания ссылки](api-account.md#post-api-agent-claim-link).

## 2. Подключите MCP-клиент

Используйте Streamable HTTP по адресу `https://web3alert.io/mcp/agent`. Список инструментов доступен без токена. Для вызовов передавайте `Authorization: Bearer <agent-key>`.

### Claude Code

Задайте ключ агента в переменной `WEB3ALERT_KEY` в терминале и выполните эту команду.

```bash
claude mcp add --transport http web3alert-agent https://web3alert.io/mcp/agent \
  --header "Authorization: Bearer $WEB3ALERT_KEY"
```

### Claude Desktop и Cursor

Добавьте запись в `mcpServers` в файле `claude_desktop_config.json` для Claude Desktop (Settings → Developer → Edit Config) или в личном файле `~/.cursor/mcp.json` для Cursor. В примере используется мост `mcp-remote`, который запускается через `npx`. Замените пример ключа своим значением.

```json
{
  "mcpServers": {
    "web3alert-agent": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://web3alert.io/mcp/agent",
        "--header",
        "Authorization:${AUTH_HEADER}"
      ],
      "env": {
        "AUTH_HEADER": "Bearer YOUR_AGENT_KEY"
      }
    }
  }
}
```

### VS Code

Для подключения через редактор добавьте запись в `servers` в файле `.vscode/mcp.json` и передайте переменную `WEB3ALERT_KEY` в окружение процесса VS Code.

```json
{
  "servers": {
    "web3alert-agent": {
      "type": "http",
      "url": "https://web3alert.io/mcp/agent",
      "headers": {
        "Authorization": "Bearer ${env:WEB3ALERT_KEY}"
      }
    }
  }
}
```

## 3. Пополните баланс и купите тариф

1. Вызовите `get_topup_requirements({"amountEur":5})` с правом `manage`. Пополнение от 5 до 500 € оплачивается в USDC в сети Base. Web3alert применяет справочный курс ЕЦБ для USD, считает 1 USDC равным 1 USD и не добавляет наценку.
2. Оплатите котировку своим клиентом x402 v2 и кошельком. Отправьте возвращённый `body` методом `POST` на полученный `url` с Bearer-ключом и подписью платежа в `PAYMENT-SIGNATURE`. Дождитесь расчёта по [пополнению](api-billing.md#post-api-billing-wallet-x402-topup) и зачисления средств на баланс в EUR.
3. Вызовите `buy_plan({"planId":"advanced","durationMonths":1,"requestId":"first-plan-001"})` с правом `spend` и достаточным балансом. Advanced или Pro можно купить на 1, 3, 6 или 12 месяцев без автопродления. При повторе используйте те же `requestId` и параметры покупки.

## 4. Создайте первую подписку

Выберите публичный HTTPS-вебхук или, на Advanced и Pro, входящие события рабочего пространства (inbox). Для добавления вебхука, создания подписки, чтения входящих событий и истории доставок нужна роль `owner` или `admin`.

### Доставка на вебхук

В этом примере заменяйте значения в угловых скобках результатами предыдущих вызовов. Вместо адреса из примера укажите HTTPS-адрес своего вебхука без имени пользователя и пароля. Выберите событийный триггер и передайте обязательные `inputs`, которые покажет `get_trigger`. В примере у триггера нет обязательных входных параметров.

1. `get_account({})` → Аккаунт, тариф, текущий воркспейс, баланс кошелька в EUR, лимиты тарифа и счётчики подписок, если они доступны.
2. `find_triggers({"kind":"event","limit":5})` → Подходящие триггеры из опубликованного каталога и текущего воркспейса, включая `fullname` каждого триггера.
3. `get_trigger({"trigger":"<trigger-fullname>"})` → Входные параметры триггера, поля события и поля для фильтрации.
4. `add_webhook({"name":"agent-events","url":"https://example.com/webhooks/web3alert"})` → `fullname`, имя и URL зарегистрированного вебхука. Секрет подписи доступен только в ответе `add_webhook` в поле `signingSecret`. Если заменить его позже, секрет изменится для всех получателей этого эндпоинта. Сохраните секрет для принимающей стороны.
5. `create_subscription({"trigger":"<trigger-fullname>","webhook":"<webhook-fullname>","state":"on"})` → ID, название, итоговое состояние, триггер и вебхук подписки.
6. `get_delivery_log({"subscriptionId":"<subscription-id>"})` → Результаты доставки и `nextCursor`, если есть ещё результаты. Для истории оповещений используется тариф первого аккаунта с ролью владельца в списке доступа воркспейса. Если такого аккаунта нет, API проверяет тариф аккаунта, который сделал запрос. Если в тариф не входит история, инструмент возвращает `not_in_plan`.

   Если курсор не может продвинуться из-за того, что у 500 или более доставок одна и та же отметка времени, инструмент возвращает `api_error`. Уточните фильтр, например по статусу, и начните заново без курсора.

Убедитесь, что подписка вернулась со значением `state` равным `on`. После этого вебхук может получать подходящие события. Укажите новое имя вебхука или найдите уже зарегистрированный вебхук с помощью `list_webhooks`.

### Тело запроса вебхука

Ваш вебхук получает тело в формате JSON с ID события. Новые вебхуки получают подписанные доставки, и Web3alert автоматически повторяет попытки при сбоях, для которых предусмотрен повтор. Формат тела, проверка подписей, повторы и устранение дублей описаны в разделе [Вебхуки](webhooks.md).

### Доставка во входящие события

Найдите триггер, проверьте его параметры через `get_trigger` и вызовите `create_subscription({"trigger":"<trigger-fullname>","inbox":true,"state":"on"})`. Передайте обязательные `inputs`. Инструмент принимает один способ доставки за вызов и создаёт или переиспользует inbox рабочего пространства.

Вызовите `read_events({})`, чтобы начать с самого старого сохранённого события. Если `nextCursor` не равен `null`, сохраните и передайте его как `after` при следующем вызове. Продолжайте чтение, пока `hasMore` равно `true`, и используйте курсор для опроса. `gap: true` означает, что часть событий больше не хранится. Для дедупликации используйте `id` события.

Учитывается тариф владельца пространства, а при его отсутствии — тариф вызывающего аккаунта. Advanced хранит до **7 дней или 25 000 событий**, Pro — до **30 дней или 100 000 событий**. На Free возвращается `not_in_plan`.

## 5. Соберите триггер

На Advanced или Pro подключите клиент к `https://web3alert.io/mcp/agent/build` с тем же заголовком Bearer. Сервер генерирует триггер из ABI контракта EVM, IDL Solana или метаданных Substrate без написания кода.

1. Вызовите `find_contract` для сети платформы и укажите адрес контракта, программу Solana или паллет Substrate. В `chain` передайте короткое имя, например `ethereum`, `base`, `arbitrum-one`, `polkadot` или `solana`, либо имя в формате `common.<chain>` или `common.source.<chain>`. Если сеть неизвестна, ищите доступные имена после `Supported:` в сообщении об ошибке.

   Для EVM поле `recentBlocks` показывает, сколько недавних блоков охватывает `recentCount` каждого события, максимум 1 000. Диапазон может быть меньше, если провайдер отклонит широкий запрос. Значение `null` означает, что прочитать блоки не удалось.
2. Передайте ту же сеть и цель вместе с точной сигнатурой события в `plan_trigger`. Сохраните `draftId`. Черновик действует семь дней.
3. Вызовите `test_trigger` для черновика. Сервер может найти недавний пример, также можно указать блок или слот. Продолжайте после результата `matched` в последнем тесте.
4. Вызовите `activate_trigger` с `draftId` и своим `requestId`. Повторяйте запрос с тем же ID. Триггер сохраняется в приватном проекте агента в рабочем пространстве. Передайте полученное полное имя в `create_subscription`.

Для `find_contract` и `test_trigger` нужно право `read`, для планирования и активации — `manage`. См. [справочник инструментов сборки](mcp-server.md#build-endpoint).

## Лимиты

На тарифе Free аккаунт может иметь **до 5 созданных им активных подписок на проекты без статуса Free** суммарно во всех воркспейсах. Подписки на проекты Free не входят в лимит.

На тарифе Free для подписок с доставкой только на встроенные вебхуки по умолчанию действуют всплеск до 12 оповещений, постоянная скорость 1 оповещение в секунду и предел очереди в 15. Эти подписки не расходуют квоту доставки воркспейса.

Тариф Free позволяет делать 60 запросов в минуту к внешнему API. Тесты подписок и история оповещений доступны на тарифах Advanced и Pro. В обоих случаях API проверяет тариф первого владельца воркспейса и использует правило из шага 6, если владельца нет. Полные таблицы доступны в разделе [«Лимиты»](limits.md).

По умолчанию сервер MCP разрешает 120 вызовов инструментов на аккаунт в минуту. Все три эндпоинта используют общий лимит в каждом серверном процессе. `get_account` возвращает тариф аккаунта и те же [лимиты тарифа](api-account.md#me-limits), что и `GET /api/me`. Поле `limits` в ответе инструмента равно `null`, если API не передаёт лимиты тарифа. MCP может использовать сохранённый ответ `/me` до 30 секунд, поэтому смена тарифа может отразиться в `get_account` с такой задержкой.
